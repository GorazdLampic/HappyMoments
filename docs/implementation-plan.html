Strategy: 4 Phases, Ship After Each

Principle: Each phase produces a deployable version. No "big bang" rewrite. Each phase makes the app better on its own, even if the later phases never happen. Test with real users after each phase.

Development Process (for reference)

The pattern used for each phase:
  1. HTML first — structure the screens/elements
  2. CSS second — style them
  3. JS third — wire up the logic
  4. Test — ?reset for onboarding, normal for daily use
  5. Build + push — deploy to Cloudflare Pages, then Android via GitHub Actions

What We Protect

These are sacred (from ux-guidelines.html §8. What We Protect):

  • The billion-second hook concept
  • Counter animation on reveals
  • Pre-written share messages (1000+ templates, 6 languages)
  • PWA capability
  • 20-language support
  • Local-first data (no account required)
  • Milestone calculation engine (specialNumbers.js, milestoneCalculator.js)
  • API backend (Cloudflare Functions, D1, Stripe)
  • Android build pipeline (GitHub Actions)
  • Gold + gray color system
  • 3-tab navigation (Me | Together | Edit)
