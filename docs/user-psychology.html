The Core Insight

"HappyMoments is a relationship tool disguised as a number calculator. It gives people reasons to celebrate and reconnect."

The numbers are the excuse. The celebration is the point. The reconnection is the real value.

Two use cases, equally important:

Use caseExampleEmotional driver
Celebrate"Your daughter turns 5,000 days old next Tuesday!"Joy, marking time, parental pride
Reconnect"Hey, I just found out you turn 15,000 days next week!"The perfect non-awkward excuse to reach out

Matej Guid — Strategic UX Framework

"Za naš SaaS produkt, lahko tekmujesz le v enem od naslednjča: price, product, integrations, UX. In ko smo dojeli, da ne tekmujemo v UX, smo začeli kopirati od drugih."

For a SaaS product, you can only compete on one of: price, product, integrations, UX. When we realized we weren't competing on UX, we started copying from others.

Implication for HappyMoments: We compete on product (unique milestone engine, no competitor matches our math). So our UX should copy established patterns from apps users already know — not invent new UI paradigms. Copy from: Instagram (share flow, bottom tabs with labels + icons), WhatsApp (tab navigation), Spotify Wrapped (number reveal, tap-to-share).

Matej applied the key principles specifically to HappyMoments:

  • "Input should be minimal; show, don't ask" — you only NEED dates. Not even names at first. Start with "You", "Sister", "Friend" as labels — names can come later when the user already gets the point.
  • "Hick's Law" — at every step you lose users. ONE call-to-action button, clear next step. "Lead them by the hand" into each desired step.
  • "Design for the first 30 seconds" — that's the onboarding flow. If 30 seconds don't deliver wow, nothing else matters.
  • "Simplicity = removing what isn't essential" — sometimes it's hard to remove a piece of text from the screen. But if it isn't essential (!), it's in the way.
  • "Every element must communicate its purpose without labels" — use familiar, standardized UI elements. No custom inventions.

Matej on the Hook Model applied to HappyMoments:

  • Trigger: Calendar reminder / push notification (what causes the user to open the app)
  • Action: Add a new birthday (the main act — more dates = more happy moments)
  • Variable reward: Each new date reveals different milestones, always something new (including combinations like "together you have 2 billion seconds")
  • Investment: Adding more people, organizing groups — makes the next trigger more valuable

Matej's key directive for next version:

"When the next improved version is ready and verified good, have Claude find popular mobile apps with a similar user experience. Then copy, following the principle: Users prefer your app to work like the apps they already know."

Matej Guid — Settings cleanup (applied in v52):

  • Remove everything that isn't essential. Invite Friends, Send Feedback, Save Settings, and Reset All Data were removed from the Edit tab. They added visual weight without clear user benefit at this stage.
  • Number Patterns and Custom Numbers moved under a collapsible "Advanced settings ▼" (hidden by default). Most users never need these — showing them upfront violates Hick's Law.
  • Theme: tiny inline dark/light toggle. No separate section needed for a binary choice.
  • Reminders: single checkbox. One control, not a settings sub-page.

Implication: The Edit tab now has a clean hierarchy: group management at top, then theme + reminders as lightweight controls, then advanced settings collapsed away. This directly applies Matej's "Simplicity = removing what isn't essential" principle.

Luka Renko — User Journey Psychology

"Moraš voditi uporabnika po točno želeni poti... ampak najprej moraš vedeti kaj ta pot sploh je."

You must guide the user on the exact desired path... but first you must know what that path is.

Implication: The onboarding is a guided story with ONE path, not a choose-your-adventure. MY date → MY hero → MY milestones → add ONE person → THEIR reveal → combined → group builder → group reveal → share → dashboard. Linear, 9 screens, back buttons for safety.

"Vsakič, ko uporabnik nekaj izpolni, mora imeti nek občutek zadovoljstva. Nekaj se zgodi... kot nagrada."

Every time the user completes something, they must feel satisfaction. Something happens... like a reward.

Implication: After entering birthday → counter animation. After adding a person → their milestone reveal. After sharing → "Sent!" confirmation. Never: enter data → nothing visible happens.

"Ali naj uporabnik izbere le ENEGA družinskega člana... Tako potem uporabnik ne dobi občutka, da je to nek 'računovodski' program."

Should the user enter only ONE family member?... That way the user doesn't get the feeling that this is some 'accounting' program.

Implication: During onboarding, enter ONE other person first (Screen 4). ONE person, ONE reveal. Then combined milestones create the "aha!" moment, and the group builder (Screen 7) lets them add more. The key: the FIRST person addition is singular and emotional, not a form.

"Sedaj je odločno preveč teksta, slabo izbrani fonti."

Currently there is decidedly too much text, poorly chosen fonts.

Implication: Three text levels only (hero/body/caption). No tiny text. Serif for warmth, mono for numbers. See ux-guidelines.html.

Peak-End Rule (Daniel Kahneman)

People judge experiences by two moments: the peak and the end.

MomentHappyMoments implementation
PeakThe counter animation rolling up to the big number. Gold glow. Sparkle particles. This is the moment that defines the product in the user's memory.
EndEvery session ends with anticipation, not a dead screen. The Solo tab always shows upcoming milestones with countdowns — forward-looking positive emotion. Never end on: empty state, error, "no milestones today" with nothing else.

Gradual Reveal Principle (v2.0)

Progressive discovery across 9 screens. Share available at every milestone.

The onboarding never dumps all milestones at once. Instead, it layers discovery:
  1. YOUR hero — counter animation, one big number (Screen 2)
  2. YOUR milestones — 3 milestones + expand toggle, 730-day window, all tappable (Screen 3)
  3. Add ONE person — emotional pivot to "our app" (Screen 4)
  4. THEIR hero + milestones — merged on one screen, 3 milestones + expand toggle, list hidden until animation finishes (Screen 5)
  5. Combined milestones — full engine, 3 results + expand toggle, group name (Screen 6)
  6. Group builder — add more people, growing list (Screen 7)
  7. Group reveal (two-phase) — Phase 1: individual milestones for NEW members. Phase 2: combined team milestones (3 shown + expand toggle) (Screen 8)
  8. Share screen — "Another circle of people?" + tab guide, then dashboard (Screen 9)

Why: Showing 20 milestones at once is overwhelming (Miller's Law). The 9-screen flow creates anticipation at every step (Spotify Wrapped model). Share is available at every milestone screen via tap → gold highlight (ms-selected) + floating "Share →" bubble at bottom center.

In daily use: The Solo tab shows a flat time-chunked list with all people's milestones. No hero card — all milestones equal. Person filter at top lets users focus on one person if desired.

The 5 UX Principles We Follow

Distilled from 25 researched (see archive/ux-research-strategic.md for the full list). These 5 are the ones that most directly shape our decisions:

1. Value Before Identity (from Duolingo)

Deliver the product's value before asking for ANY user data. We don't ask for name, email, sign-in, or preferences before showing the first milestone. The ONLY input is birthday — and that IS the product.

2. One Thing Per Screen (from Apple HIG, Luke Wroblewski)

Each screen has ONE primary action. In onboarding, the reveal IS the screen. In daily use, the Solo tab's time-chunked list IS the screen. Don't add navigation, options, or secondary features that compete with the primary element.

3. Hick's Law (from Jon Yablonski)

More choices = more time = more drop-off. This is why we have 3 tabs (Solo/Together/Edit), not 4+. Why the Solo tab shows a simple time-chunked list with no hero card competing for attention. Why settings are on the Edit tab, not displayed as toggles on the main screen.

4. Emotional Framing (from Spotify Wrapped)

"788 hours finding yourself" beats "47,283 minutes listened." Numbers must tell a story. "20,000 days alive" should feel like an achievement, not a statistic. The countdown text uses emotional language: "That's this week!" not "7 days from now."

5. Design the Shareable Artifact First (from Spotify Wrapped team)

If it can't be screenshotted and posted, it won't go viral. Every milestone card, every reveal screen, every share message is designed to look good when shared. The share flow produces beautiful 9:16 image cards for Instagram/Stories, not just text.

Persona Archetypes

Four primary archetypes (distilled from 15 personas researched):

1. The Parent (age 30-50)

Goal: Track children's milestones. Share with family.
Emotional driver: Parental pride, marking time passing, creating memories.
Key feature: Solo tab showing their child's next milestone at top of list. "Your daughter turns 5,000 days old on..." → tap to share to family WhatsApp group.
Retention: Milestone notifications for their children.

2. The Reconnector (age 25-45)

Goal: Find an excuse to reach out to someone they've lost touch with.
Emotional driver: Longing, friendship, non-awkward excuse.
Key feature: Pre-written share message. "Hey, I just found out you turn 15,000 days next week!" → one-tap send.
Retention: App reminds them of friends' milestones they'd otherwise forget.

3. The Number Nerd (age 18-35)

Goal: Discover mathematical patterns in time. Self-discovery.
Emotional driver: Intellectual curiosity, "cool factor," social currency.
Key feature: Fibonacci, palindromes, cosmic cycles, Pi connections.
Retention: There's always another interesting number coming.

4. The Family Organizer (age 35-60)

Goal: Track the whole family, discover group milestones.
Emotional driver: Family identity, connection, celebration planning.
Key feature: Combined milestones ("Your family's combined age reaches 100,000 days!"). Multiple people.
Retention: The app becomes more valuable as more family members are added.

Content Freshness: Why Users Return

The app must have something NEW on every visit:

FrequencyWhat's newSource
Every daySolo tab countdowns change. "12 days" → "11 days" → "10 days"Automatic (time passes)
Every weekDifferent milestone becomes the hero (closest one rotates)Automatic (milestone dates approach)
Every monthNew milestones enter the "Coming up" viewAutomatic (year-long horizon)
Each person added~20 new milestones appear in the timelineUser-driven
Each milestone sharedSocial reactions create external reward loopUser-driven
The fundamental retention insight: Unlike social media (which needs new content), HappyMoments generates fresh content AUTOMATICALLY from the passage of time. Every day, the countdown changes. Every week, a new milestone becomes the closest one. The user doesn't need to "do" anything — time creates value.
The engagement depth insight (v78): Your own milestones are interesting once. Other people's milestones drive daily use — because they create a reason to reach out, share, and reconnect. The app's value is in the ACTION (sending a message to Mom, celebrating with Partner) not the INFORMATION (knowing your own number). This is why the second-group engagement flow matters: users with 2+ groups have 3× more reasons to return.

Second-group nudge: Together tab shows "Got another circle?" when only 1 group exists. Screen 8 offers "Create another group" after the first group reveal. Screen 9 shows "Another circle of people?" alongside "Go to dashboard." Once the user has 2+ groups, the prompts disappear and the tab guide text (Solo / Together / Edit descriptions) appears instead.
Screen 8 two-phase psychology (v78): The group reveal is split into two phases to teach the user both core use cases during onboarding:

Phase 1 — Individual reach-out motivation: "Imagine their face when you tell them." Shows individual milestones for new members only. Smart display: 1 member = 3 milestones + expand, 2+ members = 1 each + expand per person. The emotional driver is personal connection — the user sees a specific milestone for a specific person and feels the impulse to reach out. This trains the "reconnection" use case.

Phase 2 — Group celebration motivation: "These milestones belong to all of you. [random continuation]" (same font, one sentence). Hero milestone is tappable to share and not duplicated in the list below. Shows combined team milestones. The emotional driver is collective identity — the group has milestones together that no individual has alone. This trains the "celebrate together" use case.

Post-share button promotion: After the user shares, the "Share with your group" button is demoted to secondary, while "Who else? Add another group" and "Go to my dashboard" are promoted to primary. This guides users toward creating more groups after their first share, increasing engagement depth.

This separation ensures the user experiences both emotional triggers (individual reach-out AND group celebration) before leaving onboarding.
Age-appropriate group examples (v78): When creating a second group (Screen 6 repurposed), the app shows age-appropriate rotating examples to suggest contextual use cases: ≤20 years old sees school examples, 21-25 sees university examples, 26+ sees office/workplace examples. This makes the "create another group" prompt feel relevant and personal rather than abstract.
