What's wrong with it

2. Navigation Options: What the Research Says

Hard data from NNGroup: Hidden navigation (hamburger menu) causes 21% increase in perceived difficulty, 15-39% slowdown, and 20%+ drop in feature discoverability. Bottom tab bars win decisively. Optimal: 3-5 tabs. Never more than 5.

Option A: 3 tabs (radical simplicity)

[ Home ] [ People ] [ Profile ]
TabWhat's in it% of usage
HomeHero milestone + upcoming list + combined milestones + "Today's number"70%
PeopleAdd/edit people, manage dates, see per-person milestones20%
ProfileSettings, theme, language, notifications, legal, account10%

Pros: Maximum simplicity. "Home" gets full attention. Zero confusion about where to go.

Cons: Combined/team milestones buried inside Home — might feel crammed. People tab does double duty (add + view).

Option B: 4 tabs (current count, better names)

[ Home ] [ Together ] [ People ] [ More ]
TabWhat's in it% of usage
HomeHero milestone + personal milestone list60%
TogetherCombined milestones for families/couples/groups15%
PeopleAdd/edit people and dates15%
MoreSettings, theme, notifications, gift store, legal, export/import10%

Pros: "Together" is a clear, warm label (better than "Team"). "More" is a known pattern (Instagram used it). Keeps combined milestones discoverable.

Cons: Still 4 tabs. "More" is a catch-all that some UX purists dislike.

Option C: 3 tabs + contextual access

[ Home ] [ People ] [ ☰ ]
TabWhat's in it
HomeHero + personal + combined (interleaved timeline, not separate tab). "Together" milestones appear in the same list, marked with a family icon.
PeopleAdd/edit people. Tap a person → see their milestones.
☰ (menu)Settings, notifications, theme, gift store, legal, export

Pros: Combined milestones flow naturally into the main timeline — no separate tab to discover. Hamburger only for rarely-used settings (acceptable per NNGroup: "use hamburger for secondary items"). 2 real tabs + 1 utility.

Cons: Combined milestones might get lost in the main list. Hamburger for settings is OK per research, but some users won't find it.

Option D: Hub-and-spoke (app opens to a dashboard)

┌──────────────────────────────┐ │ ★ Next milestone: 12 days │ ← Hero card │ Mom turns 20,000 days │ │ [Share] [Remind me] │ ├──────────────────────────────┤ │ This week │ This month │ ← Time-chunked list │ ○ Dad: 888d │ ○ You: 12000d │ │ ○ Sis: 3000w│ ○ Wed: 5000d │ ├──────────────────────────────┤ │ [👤 People] [⚙ Settings] │ ← Cards, not tabs │ [👨‍👩‍👧 Together] [🎁 Gifts] │ └──────────────────────────────┘

Pros: Dashboard pattern (like Revolut Home). All features visible as cards. No tabs at all — each card opens a full-screen sub-view, user returns to hub. Strongest for feature discovery.

Cons: Requires more scrolling. Sub-views need clear "back to home" navigation. Not a standard mobile pattern — users might feel lost.

3. Recommendation: Option A or C

My recommendation: Option A (3 tabs) for the beta launch. It's the simplest, most opinionated structure. Home absorbs everything the user cares about on a daily basis. People is the "management" area. Profile catches the rest.

If combined/team milestones prove popular (track with analytics), promote to Option B by adding a "Together" tab later. It's easier to add a tab than to remove one.

How "Home" would work (the key question)

Home is a single scrollable screen with sections that appear based on what the user has:

┌──────────────────────────────────┐ │ │ │ ★ HERO MILESTONE │ One card. The most exciting │ Mom turns 20,000 days │ milestone coming up. Big number, │ June 18 — in 12 days! │ share button, remind button. │ [Share] [Remind me] │ │ │ ├──────────────────────────────────┤ │ │ │ COMING UP │ Time-chunked milestone list. │ This week │ Max 5-7 items per chunk. │ Dad · 888 days · Tue │ Tap any → share or details. │ You · 500 months · Thu │ │ This month │ │ Sister · 12,321 days · Jun 22 │ │ Wedding · 3,000 days · Jun 28 │ │ Later │ │ You · 1B seconds · Aug 14 │ │ │ ├──────────────────────────────────┤ │ │ │ TOGETHER (if 2+ people) │ One combined milestone teaser. │ You + Mom = 38,547 days. │ "See more combined →" │ 40,000 together in Nov 2030. │ │ │ ├──────────────────────────────────┤ │ │ │ [+ Add someone to celebrate] │ Always visible at the bottom. │ │ └──────────────────────────────────┘

Key design decisions:

  • Hero card is weather-app style — one glanceable thing at the top. Answers "what's the most interesting milestone right now?"
  • Milestones are chunked by time (Miller's Law) — "This week" / "This month" / "Later" instead of a flat list of 50 items.
  • "Together" appears contextually — only shows when 2+ people exist. Not a separate tab, not a feature to discover — it just appears.
  • "Add someone" is always at the bottom — the growth action is persistent but unobtrusive.

4. The Onboarding → Daily Use Bridge

The brutal numbers: 77% of users stop using an app within 3 days. Day 2-4 is the most critical retention window. If the user doesn't have a reason to return within 24 hours of their first session, they probably won't.

The current problem

After our onboarding, the user sees... the dashboard. With tabs. And no guidance. They think "cool, I saw my billion" and never come back. There's no hook pulling them to Day 2.

What needs to happen at the end of Session 1

  1. A concrete reason to return tomorrow. "Your next milestone is in X days — we'll remind you." Or: "Check back tomorrow — we'll show you something new."
  2. A notification scheduled. If they enabled reminders: send the first one within 24 hours. Content: their next closest milestone. Make it personal: "Dad turns 888 days on Thursday."
  3. An investment made. They added 1-2 people. Now they have data in the app. Losing it creates switching cost.

The first 7 days: a graduated experience

DayWhat the user seesWhat we introduceGoal
Day 1Onboarding → hero reveal → add 1-2 people → shareCore: milestones + shareFirst share (activation)
Day 2Push notification: "Dad's 888 days is Thursday"The notification proves the app watches for youReturn visit
Day 3Open app → hero card updated → "Coming up" listTime-chunked list (This week/month/later)Explore depth
Day 4-5If 2+ people: "Together" section appears with a teaserCombined milestones — contextual, not forcedDiscover team feature
Day 7If 3+ people: "You have 24 milestones coming this year"The "depth" revelation — the app has ongoing valueLong-term retention

"Check and go" (30 sec) vs "Stay and explore" (5 min)

The answer is: design for "check and go" FIRST. If the user gets value in 5 seconds (hero card → "nothing today, Dad's milestone is Thursday"), they'll come back. If they have to scroll and explore to find value, they won't return daily.

The "stay and explore" mode is below the fold. It's there when they want it, but the app works perfectly as a 5-second glance.

This mirrors how people use weather apps: open, see the temperature, close. But sometimes they scroll down to the hourly forecast. The hero card IS the temperature.

5. Screen Transitions: How to Move Within the App

The rules (from Apple HIG, Material Design, NNGroup)

Transition typeWhen to useAnimation
Tab switchSwitching between Home / People / ProfileInstant crossfade (no slide). Tabs maintain scroll position.
Push (drill-down)Tapping a milestone to see details. Tapping a person to see their milestones.Slide from right. Back arrow (←) top-left to return.
Modal (bottom sheet)Share flow. Add person form. Quick actions.Slide up from bottom. Drag-to-dismiss or close (×). Doesn't replace the screen — overlays it.
Full-screen modalOnboarding. Settings sub-pages. Gift store.Slide up. Close (×) top-left. Used for focused tasks that don't need the tab bar.

Key principle: Flat, not deep

"Limit navigation to 2 levels maximum on mobile. Beyond that creates usability problems." — NNGroup

For HappyMoments:

  • Level 1: Tab bar (Home / People / Profile) — always visible
  • Level 2: Detail views (milestone detail, person's milestones, settings sub-page) — push navigation with back arrow
  • Modals: Actions (share, add person, edit) — bottom sheets that overlay, don't replace

Never deeper than 2 taps from any tab. Every screen has either a back arrow (←) or a close (×) — never ambiguous.

Tap paths (critical user journeys)

"Empty states are the most overlooked aspect of UX design — and the most impactful for first-run retention." — Toptal

Every section needs a meaningful empty state that teaches AND motivates:

8. Onboarding Flow (Revised)

Integrating the navigation and daily-use research, here's the revised onboarding:

The critical bridge: Screen 6 → Home tab must feel seamless. The hero card on Home should show the SAME milestone they just saw in Screen 2 (their own) or Screen 5 (friend's). No disorientation. The onboarding deposits them into the exact state the daily app will show.
