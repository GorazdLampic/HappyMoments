1. Design Philosophy

Less but better. HappyMoments is a relationship tool disguised as a number calculator. It gives people reasons to celebrate and reconnect. Every pixel must serve that mission. If an element doesn't help the user discover, celebrate, or share a milestone — remove it.

Four rules that override everything else:

  1. One hero per screen. Each screen has ONE dominant element. Everything else supports it.
  2. Never feel like accounting software. Numbers are celebrations, not data. Reward every action.
  3. The shareable artifact is the product. If the user can't screenshot it and send it, we failed.
  4. Copy, don't invent. We compete on product (unique milestone engine), not on UX. Every UI pattern should feel familiar — copied from apps users already use (Instagram, WhatsApp, Spotify, Weather). No custom navigation, no novel gestures, no invented UI concepts. (Matej Guid: "Users prefer your app to work like the apps they already know.")

Two semantic colors. Nothing else.

One gold element per screen. (Von Restorff Effect) If everything is gold, nothing stands out. The hero number is gold. The CTA button is gold. Dates, names, descriptions are gray. No green WhatsApp buttons, no blue links, no red badges. Gold and gray.

Font families

  • Words: 'EB Garamond', 'Georgia', 'Cambria', serif — warm, literary, human

7. Accessibility

  • Contrast: 4.5:1 minimum (WCAG AA). Gold on dark bg = 7.2:1 ✓
  • Touch targets: 44×44px minimum (Apple HIG)
  • Text: never below 14px. Body 17.6px.
  • Zoom: pinch-to-zoom enabled (user-scalable=yes)
  • VoiceOver: all milestone values have aria-label with full text ("twenty thousand days")
  • Reduced motion: respect prefers-reduced-motion — skip counter animation, show final value immediately

8. What We Protect

These elements are sacred. They define the app. Do not remove or significantly alter them without explicit founder approval:

  • The billion-second hook (first onboarding screen)
  • Counter animation on milestone reveal
  • Pre-written share messages (1000+ templates, 6 languages)
  • Column layout for per-person milestones (returning users)
  • PWA capability (works offline, installable)
  • 21-language support with auto-detection
  • Local-first data (no account required)
  • Gold + gray color system

9. Number Quality Guidelines

Palindrome quality hierarchy

Not all palindromes are equally impressive. Palindromes with internal order are the strongest:

TierPatternExamplesWhy it's good
Tier 1: MountainDigits ascend then descend12321, 1234321, 123454321Instantly recognizable pattern. Beautiful symmetry. People go "wow" immediately.
Tier 2: Round palindromeZeros create visual balance10001, 100001, 1000001Clean, impressive-looking. Easy to understand.
Tier 3: Repeated coreSingle digit core repeated1221, 5005, 9009, 12321Simple structure, recognizable.
Tier 4: GenericReads same forwards/backwards but no additional order14241, 27372Valid palindrome but less visually striking. Show only in days/years, filter from seconds/minutes/hours.

Repdigit coverage

All repdigits (111, 222, 333, ... 999, 1111, 2222, ... 9999, 11111, ...) are generated up to 11 digits. This is comprehensive. Repdigits are universally recognized as "special" across all cultures.

Default-off patterns

v1.2 Update:
Fibonacci: OFF by default. Numbers like 17,711 or 46,368 are not recognizable — they look random. Available as opt-in in Profile → Advanced.

Powers of 2: Show up to 210 = 1,024 only. Everyone knows 2, 4, 8, 16, 32, 64, 128, 256, 512, 1024. These should be displayed with their power notation: "128 days (27)" or "512 hours (29)". Beyond 1,024 (2,048, 4,096, 8,192...) — OFF by default, available in Advanced.

Coherence filter reminder

See navigation-architecture.html §Milestone Coherence Rules for the per-unit filter that prevents ugly numbers from showing.
